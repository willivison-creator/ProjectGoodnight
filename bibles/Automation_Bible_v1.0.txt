# PROJECT GOODNIGHT

## Automation Bible

### Version 1.0

---

# Purpose

The Automation Bible defines every automated process required to produce a nightly episode of "Goodnight, Jackson."

The goal is a fully automated production pipeline that requires no manual intervention under normal operating conditions.

The system should be modular, fault tolerant, observable, and easily maintainable.

Automation should prioritize reliability over speed.

---

# Guiding Principles

Automation should be:

• Modular
• Observable
• Repeatable
• Recoverable
• Version Controlled

Every step should perform one responsibility.

No component should perform multiple unrelated tasks.

---

# Module 1

Scheduler

Purpose

Launch the nightly workflow.

Requirements

• Runs automatically.
• Supports manual execution.
• Supports retry.
• Records execution time.

Inputs

Date

Time

Configuration

Outputs

Workflow ID

Timestamp

Execution Log

---

# Module 2

Research Engine

Purpose

Collect candidate stories.

Sources may include:

National news

International news

Sports

Mississippi news

Jackson-area news

Weather

Positive community stories

Requirements

Return structured data only.

Never summarize.

Never rank.

Output

Structured news objects.

---

# Module 3

Editorial Engine

Purpose

Select stories.

Responsibilities

Remove duplicates.

Rank importance.

Apply Editorial Bible.

Limit story count.

Output

Episode Outline

---

# Module 4

Script Engine

Purpose

Write the episode.

Requirements

Follow Editorial Bible.

Follow Production Bible.

Maintain runtime.

Maintain tone.

Output

Episode Script

Purpose

```
/MM/

    /DD/
```

# Error Handling

Every failure should have a recovery strategy.

Research Failure

Retry.

Editorial Failure

Restart editorial stage.

Audio Failure

Retry generation.

Publishing Failure

Retry upload.

Archive Failure

Alert operator.

The workflow should recover from partial failures whenever possible.

---

# Notifications

Upon completion send a notification containing:

Episode number

Runtime

Publication status

Any warnings

Link to assets

Failure notifications should include diagnostic information.

# Disaster Recovery

Every production should be reproducible.

Archive:

Scripts

Metadata

Logs

Audio

Video

Prompt versions

Bible versions

Workflow version

If an episode must be regenerated, the system should know exactly which inputs produced the original.

---

# Version Control

Automation workflows are source-controlled.

Every release includes:

Workflow Version

Prompt Versions

Bible Versions

Software Versions

Configuration Version

This ensures complete reproducibility.

---

# Definition of Success

The automation succeeds when a listener cannot distinguish whether an episode was created manually or automatically.

The workflow should complete with minimal operator intervention while preserving the editorial, production, and audio standards established by the governing Bibles.

Automation exists to protect consistency—not replace craftsmanship.
